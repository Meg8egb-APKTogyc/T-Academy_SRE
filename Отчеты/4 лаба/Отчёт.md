# Отчёт по ДЗ: Victoria Metrics + экспорт метрик приложения

## 1. Стек и развёртывание Victoria Metrics

- **Victoria Metrics (single-node)**: развёрнута в namespace `monitoring` через официальный Helm-чарт `victoria-metrics-single`.
- **vmagent**: развёрнут через Helm-чарт `victoria-metrics-agent`. Отвечает за сбор (scraping) метрик и отправку их в Victoria Metrics.
- **Spring Boot Actuator + Micrometer**: в приложение добавлена зависимость `micrometer-registry-prometheus`, открыт эндпоинт `/actuator/prometheus`.
- **PostgreSQL Exporter**: развёрнут как sidecar-контейнер (`prometheuscommunity/postgres-exporter`) в поде с базой данных, собирает метрики СУБД.

## 2. Использованные экспортеры

1. **Рантайм и фреймворк (Pull)**: эндпоинт `/actuator/prometheus` на порту 8080. Отдаёт JVM-метрики (память, GC, потоки), метрики Tomcat и HikariCP.
2. **PostgreSQL (Pull)**: `postgres-exporter` на порту 9187. Отдаёт метрики базы данных (количество подключений, транзакции, `pg_up`).
3. **Бизнес-метрики (Pull)**: реализованы в приложении с помощью `MeterRegistry` (Micrometer) и отдаются через тот же эндпоинт Actuator.

## 3. Реализованные бизнес-метрики (4 шт.)

В классе `BusinessMetrics.java` реализованы следующие метрики:

| Имя в коде (Micrometer)  | Имя в Prometheus        | Тип     | Описание                                       |
| ------------------------ | ----------------------- | ------- | ---------------------------------------------- |
| `tasks_created_total`    | `tasks_total`           | Counter | Общее количество созданных задач               |
| `tasks_completed_total`  | `tasks_completed_total` | Counter | Количество задач, переведённых в статус DONE   |
| `projects_created_total` | `projects_total`        | Counter | Общее количество созданных проектов            |
| `tasks_in_progress`      | `tasks_in_progress`     | Gauge   | Текущее количество задач в статусе IN_PROGRESS |

## 4. Сбор метрик (Service Discovery)

Для динамического обнаружения таргетов `vmagent` использует `kubernetes_sd_configs` (роль `pod`).
В манифесты деплойментов `backend` и `postgres` добавлены аннотации:

- `prometheus.io/scrape: "true"`
- `prometheus.io/port: "8080"` (для backend) / `"9187"` (для postgres)
- `prometheus.io/path: "/actuator/prometheus"` (для backend) / `"/metrics"` (для postgres)

Конфигурация `relabel_configs` в `vmagent-values.yaml` фильтрует поды по этим аннотациям и перенаправляет запросы на нужные порты и пути.

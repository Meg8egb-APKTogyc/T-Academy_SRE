# Отчёт по ДЗ №2: запуск приложения в Kubernetes (Minikube)

## 1. Абстракции Kubernetes

| Абстракция | Где используется | Зачем |
|---|---|---|
| **Namespace** | `task-tracker` | Изоляция ресурсов ДЗ от системных |
| **Secret** | `db-secret` | Хранение кредов PostgreSQL (user/password/db) |
| **ConfigMap** | `app-config` | Несекретные настройки: DB_HOST, DB_PORT, DB_NAME, SERVER_PORT, INSTANCE_ID, SEED_DEMO |
| **PersistentVolumeClaim** | `postgres-pvc` | Данные PostgreSQL переживают пересоздание пода |
| **Deployment** | `postgres`, `backend`, `frontend` | Управление репликами, rolling update |
| **Service (ClusterIP)** | `db`, `backend` | Внутренний DNS и балансировка |
| **Service (NodePort)** | `frontend` | Доступ к UI с хоста на порту 30080 |
| **Job** | `migrate` | Одноразовый накат Flyway-миграций |
| **readinessProbe / livenessProbe** | postgres, backend, frontend | Автоматическое обнаружение сбоев |
| **envFrom / valueFrom** | backend, migrate | Прокидование ConfigMap и Secret в контейнеры |

## 2. Взаимодействие сервисов

```
[Пользователь]
      │ http://192.168.49.2:30080
      ▼
┌─────────────┐    proxy /api    ┌─────────────┐
│  frontend   │ ───────────────► │  backend    │
│  (nginx)    │   backend:8080   │  (Spring)   │
└─────────────┘                  └──────┬──────┘
                                        │ db:5432
                                        ▼
                                 ┌─────────────┐
                                 │  postgres   │
                                 │  (db)       │
                                 └─────────────┘
                                        ▲
                                        │ JDBC
                                 ┌─────────────┐
                                 │  migrate    │
                                 │  (Job)      │
                                 └─────────────┘
```

- **frontend → backend**: nginx проксирует `/api/` на `http://backend:8080` (DNS-имя Service `backend`).
- **backend → db**: JDBC по `jdbc:postgresql://db:5432/tasktracker` (DNS-имя Service `db`).
- **migrate → db**: Flyway по `FLYWAY_URL` с тем же хостом `db`.
- **Пользователь → frontend**: NodePort `30080` на IP Minikube.
- **Порядок старта**: `db` (healthy) → `migrate` (exit 0) → `backend` (healthy) → `frontend`.

## 3. Команды для развёртывания

```bash
# Сборка образов внутри Minikube
eval $(minikube docker-env)
docker build -t task-tracker-backend:1.0.0 .
docker build -t task-tracker-frontend:1.0.1 ./frontend
docker build -t task-tracker-migrate:1.0.0 -f migrate/Dockerfile .

# Либо: собрать локально и загрузить
minikube image load task-tracker-backend:1.0.0
minikube image load task-tracker-frontend:1.0.1
minikube image load task-tracker-migrate:1.0.0

# Применение манифестов
kubectl apply -f k8s/
kubectl get pods -n task-tracker
kubectl get all -n task-tracker

# Доступ к UI
minikube service frontend -n task-tracker --url
```

## 4. Масштабирование

```bash
kubectl scale deployment backend -n task-tracker --replicas=3
kubectl get pods -n task-tracker
```

Service `backend` автоматически балансирует трафик между репликами (round-robin по эндпоинтам).
